# AeroFlow Agent Instructions

Перед выполнением любой задачи необходимо изучить:

1. aeroflow-docs/README.md
2. aeroflow-docs/architecture.md
3. aeroflow-docs/domain-model.md

Документация является источником истины.

Если документация противоречит коду, необходимо сообщить о расхождении и следовать документации.

## Вторичный справочный источник

`aeroflow-docs/legacy-sao-user-guide.md` описывает поведение старой САО и полезен
для понимания ожидаемого UX диспетчера и требований миграции. Его **нужно
учитывать** при проектировании, но он **не является 100% правилом** — это
материал для обсуждения, а не источник истины.

При противоречии приоритет всегда у `README.md`, `architecture.md` и
`domain-model.md`. Legacy-поведение, не подтверждённое этими тремя документами,
выносится в обсуждение, а не реализуется как обязательное.

# Архитектурные правила

## Разделение ответственности

### aeroflow-core

Содержит бизнес-логику системы.

Отвечает за:

* рейсы;
* расписание;
* объявления;
* пользователей;
* аудит.

Не должен воспроизводить аудио напрямую.

---

### aeroflow-playback

Отвечает за очередь воспроизведения.

Не должен содержать сущности:

* Flight
* FlightSchedule
* Gate
* CheckInCounter

Playback работает только с PlaybackJob.

---

### aeroflow-agent

Отвечает только за воспроизведение аудио.

Не должен содержать бизнес-логику аэропорта.

---

# Правила разработки

* Использовать PHP 8.4+
* Использовать Symfony
* Следовать DDD-подходу
* Использовать Value Objects там, где это оправдано
* Использовать Symfony Messenger для сообщений
* Избегать анемичных доменных моделей
* Предпочитать композицию наследованию
* Крупные рефакторинги выполнять в отдельных git-ветках, не напрямую в основной
  ветке репозитория

---

# Перед генерацией кода

Всегда определять:

* к какому bounded context относится задача;
* является ли изменение доменным или инфраструктурным;
* какие события должны публиковаться;
* какие агрегаты затрагиваются.

---

# Основные агрегаты

* Flight
* Announcement
* PlaybackJob
* AudioAsset

---

# Основной принцип

Core отвечает на вопрос:

"Что должно произойти?"

Playback отвечает на вопрос:

"Когда это воспроизвести?"

Agent отвечает на вопрос:

"Как это воспроизвести?"
